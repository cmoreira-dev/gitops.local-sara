# gitops.local-sara

GitOps deployment for **Sara** — ArgoCD Applications and Helm values for
[`api.ia.local-sara`](https://github.com/cmoreira-dev/api.ia.local-sara)
and [`ui.ia.local-sara`](https://github.com/cmoreira-dev/ui.ia.local-sara).

## Layout

```
gitops.local-sara/
├── argocd/
│   ├── sara-api.yaml   → Application pointing at helm/api
│   └── sara-ui.yaml    → Application pointing at helm/ui
└── helm/
    ├── api/            → generic-app wrapper chart, values for api.ia.local-sara
    └── ui/             → generic-app wrapper chart, values for ui.ia.local-sara
```

Unlike the one-app-per-repo `gitops.template` default (empty `argocd/`,
auto-generated by the `gitops-repos` ApplicationSet), this repo ships two
independently-deployed components from one repo, so `argocd/` is
populated manually with both Applications.

## Routing

Both apps share the `local.cmoreira.dev` hostname (NGINX Gateway Fabric,
already tunneled) under different paths:

- **UI** — `local.cmoreira.dev/sara`. The Next.js app has `basePath:
  "/sara"` baked in at build time.
- **API** — `local.cmoreira.dev/sara/api`. The `/sara/api` prefix is
  stripped by the HTTPRoute's `URLRewrite` filter before hitting the
  container, so `api.ia.local-sara`'s own routes stay plain (`/health`,
  `/search`, ...). Gateway API's longest-prefix-match resolves `/sara/api`
  over the UI's `/sara` catch-all with no extra config.

## No ExternalSecrets

Neither app needs one: `api.ia.local-sara` is a public Cifra Club scraper
with no API keys, and `ui.ia.local-sara`'s build-time config
(`NEXT_PUBLIC_API_URL`, `NEXT_BASE_PATH`) isn't a runtime secret.

## Chart dependencies

Both `helm/api` and `helm/ui` depend on `gitops.generic-app-chart`
published to `oci://ghcr.io/cmoreira-dev/charts`. After bumping a
dependency version, regenerate the committed lockfiles:

```bash
helm dependency update helm/api
helm dependency update helm/ui
```
